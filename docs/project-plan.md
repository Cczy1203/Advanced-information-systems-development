# Project plan

## Sprint structure
### Sprint 0 – Project bootstrapping and architecture foundation
**Goal:** create the shared repository, project governance and technical baseline.

**Acceptance conditions:**
- Shared repository has a clear folder structure and initial README.
- Team roles and ownership are documented.
- Initial backlog is created with first and second owner assignments.
- BPMN starter skeleton exists.
- Service and worker scaffolding is ready for development.

### Sprint 1 – BPMN and referral flow
**Goal:** produce an executable process for referral intake, consultant review and appointment planning.

**Acceptance conditions:**
- Referral intake and consultation pathways are represented in BPMN.
- User tasks and service tasks are mapped to process responsibilities.
- Alternate and exception routes are captured.
- Key process variables are documented.

### Sprint 2 – Worker integration and forms
**Goal:** connect workflow tasks to external workers and user-facing forms.

**Acceptance conditions:**
- Service workers handle some or all automated tasks.
- Forms capture required data and pass variables correctly.
- Process and task integration is demonstrated and tested.

## Roles and responsibilities
- Project lead / coordination: to be assigned by group
- BPMN owner: to be assigned by group
- Worker implementation owner: to be assigned by group
- Form owner: to be assigned by group
- Quality and test owner: to be assigned by group

## Agile evidence required
- Backlog updates after each review
- Meeting log with blockers and decisions
- Handover notes when tasks are transferred
- Test evidence from each sprint
- Final review snapshot before submission

## Project constraints
- Clinical, administrative and financial permissions must remain distinct.
- External service failures and communication gaps must be recorded and routed appropriately.
- Audit records and patient identity protection must be considered throughout implementation.
